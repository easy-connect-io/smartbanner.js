# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

This is easy-connect's fork of [ain/smartbanner.js](https://github.com/ain/smartbanner.js). Customer websites load its `dist/smartbanner.min.js` from `https://code.easy-connect.io/smartbanner/`, and **merging a change to `dist/` or `icons/` into `main` deploys it to every one of them** (`.github/workflows/deploy.yml`). The README's "easy-connect fork" section lists where the fork behaves differently from upstream's documentation; read it before changing behaviour.

## Commands

```bash
npm run eslint          # lint src/
npm test                # run tests with coverage (mocha + c8)
npm run build           # production build (minified JS + CSS + license banner); runs prebuild first
npm run prebuild        # dev build (unminified JS + CSS, regenerates src/smartbanner-styles.js)
npm start               # dev build + watch mode + local server at :8080
scripts/check-dist.sh   # rebuild and fail if the committed dist/ doesn't match src/ (CI runs it)
```

Run a single test file:
```bash
npx mocha test/spec/smartbanner_spec.js
```

## Architecture

The library reads configuration from `<meta name="smartbanner:*">` tags in the page and renders a dismissible banner for iOS/Android users.

**Source modules** (`src/`):
- `index.js` — entry point; instantiates `SmartBanner` on `window.load`. If `smartbanner:api` meta is set to `true`/`yes`, exposes the instance at `window.smartbanner` for manual control; otherwise auto-calls `publish()`. A script that only runs after `load` (added by a consent or tag manager) initialises straight away; upstream waits for `load` forever there.
- `smartbanner.js` — main class. `publish()` prepends a `.js_smartbanner` host `<div>` to `<body>`, attaches an open shadow root and renders the banner and its inlined styles inside it, so the host page's CSS can't reach the banner. The `smartbanner--<position>` class places it: `top` (default, in the page flow), `top-absolute` or `bottom` (fixed). It never moves page content: `restoreContentPosition()`, the `originalTop`/`originalTopMargin`/`positioningDisabled` getters and the `datas` attributes are upstream leftovers nothing calls. `exit()` removes the host and bakes the close cookie. Emits DOM events: `smartbanner.init`, `smartbanner.view`, `smartbanner.exit`, `smartbanner.clickout`.
- `optionparser.js` — reads all `<meta>` tags, filters those with `name="smartbanner:*"`, and returns options as camelCase keys (e.g. `button-url-apple` → `buttonUrlApple`).
- `detector.js` — UA-based platform detection (`android`/`ios`). iOS 13+ iPad detection uses `maxTouchPoints` because the UA reports as desktop Safari. `jQueryMobilePage()` and `wrapperElement()` only serve the dead positioning code above.
- `bakery.js` — manages the `smartbanner_exited=1` cookie. `bake(hideTtl, hidePath)` sets it; `baked` getter checks it. When `hideTtl` is falsy the cookie has no expiry (session-only); `hidePath` defaults to `/` (site-wide).
- `smartbanner-styles.js` — generated by `scripts/inline-css.js` from `smartbanner.scss`. Don't edit it by hand.

**Build pipeline**: `prebuild` compiles `src/smartbanner.scss` into `dist/smartbanner.css` and into `src/smartbanner-styles.js` (compressed, imported by the bundle), then esbuild bundles `src/index.js` → `dist/smartbanner.js` targeting ES2015. `build` then writes the minified `dist/smartbanner.min.{css,js}`, and `add-banner` prepends the license header from `banner.tmpl`. The banner's styles ship inside the JS; the CSS files in `dist/` are by-products no customer page needs. Commit `dist/` with every `src/` change: CI fails otherwise, and the deploy only uploads what's committed.

**Tests**: Mocha + Chai running in Node.js with JSDOM to simulate a browser environment. Tests set up a DOM string (including relevant meta tags and UA overrides) and import source modules directly as ESM.

**Icons**: `icons/<saleschannel>.png` (192 px, from each app's iOS icon in ec-platform), served at `https://code.easy-connect.io/smartbanner/icons/<saleschannel>.png` for the `icon-apple`/`icon-google` meta tags.
